# 試行錯誤の記録

試して失敗したこと、直したことを日付つきで残します。
直したことは「何が起きたか（誰が、どこで困ったか）／なぜ直したか／どう直したか」の形で書きます。

## 2026-11-02

### はじめに決めたこと（直したことではなく出発点）
- iPad の Safari で使う Web アプリ（Next.js、公開先は Vercel）。APIキーはサーバー側の .env と Vercel の設定だけに置く。
- 候補の場所と点数はプログラムで決め、Claude は父の話をもとに「候補の中だけで」順番を入れ替えて理由を一言そえる役にする。
- GitHub に送る前に、APIキーや実際の家族の情報が入っていないかを確かめる仕組み（Claude Code のフックと git のフック）を入れる。

### 手元の Mac で npm のダウンロードが通らなかった
- 何が起きたか: 開発を始めるとき、Claude が手元の Mac の作業環境で依存パッケージを取ろうとしたら、403 で止まった。GitHub への送信もできなかった。
- なぜ直したか: パッケージが取れないとビルドも動作確認もできず、初日の作業が止まってしまう。
- どう直したか: パッケージの取得・ビルド・GitHub への送信はクラウド側で行い、Mac のフォルダにはソースだけを同期する形にした。

### iOS で読み上げが始まらなかった
- 何が起きたか: 声テストページ /voice-test を作ったとき、iPad の Safari では読み上げを画面操作の外で始めると音が出なかった。
- なぜ直したか: アプリから声で話しかけるのが中心なので、読み上げが確実に鳴らないと使えない。
- どう直したか: ボタンを押した時点で一度読み上げを呼ぶようにした。のちの /talk でも、最初の一回だけ画面をさわってもらう形にしている。

### 「眼鏡、どこいった？」が2回に分かれて聞き取られた
- 何が起きたか: iPad での1回目の声テスト。聞き取り・読み上げは使えたが、「眼鏡、どこいった？」が「メガネ」と「どこいった」の2回に分かれた。
- なぜ直したか: 文の途中の「、」の短い間で聞き取りが終わってしまうと、一つの質問として扱えない。
- どう直したか: 続けて聞き取り、1.5秒黙ったら止める方式に変えた（前の方式と切り替えて比べられるようにした）。

### 「眼鏡」が「メガネ」とカタカナで返ってきた
- 何が起きたか: 同じテストで、聞き取り結果が「眼鏡」になったり「メガネ」になったりした。
- なぜ直したか: 表記が違うだけで「眼鏡の話ではない」と判断すると、父の言葉を取りこぼす。
- どう直したか: 眼鏡／めがね／メガネを同じものとして扱う lib/normalize.ts を加えた。

### iPad が自分を Mac と名乗った
- 何が起きたか: 端末を見分けようとしたところ、iPad の Safari は端末情報（UA）で「Macintosh」と名乗っていた。
- なぜ直したか: UA で判定すると、iPad なのに iPad 用の動きにならない。
- どう直したか: 端末の判定に UA は使わないことにした。

### 父が画面の「聞いています…」を読み上げてしまった
- 何が起きたか: 父が声テストをしたとき、聞き取り中のボタンに出ていた「聞いています…」をそのまま声に出して読み、それが聞き取られた。
- なぜ直したか: 画面の文字を声に出して読むのは自然なこと。そこで間違った言葉が入るのは、表示の側の問題。
- どう直したか: 聞き取り中の画面には、話してほしい言葉そのもの（「眼鏡、どこいった？」）を出すようにした。読み上げてもらえば、それがそのまま正しい入力になる。

### iPad で古い版のまま試していた
- 何が起きたか: 直した版を公開したあと、iPad で再読み込みをせずに試すと前の版のまま動いていて、結果の形式が古いままだった。
- なぜ直したか: どの版を試しているか分からないと、直ったかどうかを確かめられない。
- どう直したか: 画面に版（コミット番号）を出すようにした。

### 決まった言い方を覚えてもらう必要があるか
- 何が起きたか: 黙るまで待つ聞き方にしたあと、父が画面の言葉ではなく自分の言葉で「めがねどこにおいたかなぁ」と言った。それでも「メガネどこに置いたかな」と一回で聞き取れた。
- なぜ直したか（方針）: 言い方は人それぞれ。決まった言い方を覚えてもらうのは父の負担になる。
- どう直したか: 言葉の意味をくみ取るのはキーワードだけに頼らず、Claude にも任せる方針にした。

### 画面の字を読むのが大変だった
- 何が起きたか: YOSHI さんから「アプリの方から声で聞いてほしい。字を読むのも一苦労」と言われた。父は画面の文字を読むのに苦労していた。
- なぜ直したか: 字を読まなくても使えることが、このアプリのいちばん大事な条件。
- どう直したか: 画面を一回さわると「どうしましたか？」と声で聞き、続けて返事を聞き取る /talk を作った。分からなければ「眼鏡を探していますか？」と、はい／いいえで聞き直す（大きなボタンでも答えられる）。

### 一か所ずつ確かめる流れと、Claude による並べ替えを加えた
- 何が起きたか: /talk で「眼鏡を探している」まで分かるようになったので、次は実際に探す流れが必要になった。
- なぜ直したか: 記憶を問いただすのではなく、場所を一つずつ案内する方が父に合う。
- どう直したか: 候補の場所と点数はプログラム（lib/places.ts・lib/rank.ts）で決める。体まわりがいつも先で、時間帯と前に見つかった回数で加点する。Claude による並べ替え /api/rerank は、返事の速さを優先して Claude Haiku 5.5（考える処理なし・effort low、4秒で打ち切り）を使い、返事を候補IDに縛る。キーがない・遅い・失敗のときは、プログラムの順番のまま進む。並べ替えを待つ間は「一緒に探しましょう」と読み上げて、待ち時間を感じにくくした。

### ゆっくり話すと、途中で聞き取りが切れた
- 何が起きたか: 父に探す流れを試してもらったところ、父はゆっくり間をあけて話すので、「さっき新聞を読んでたけど…」の途中で聞き取りが切れた。
- なぜ直したか: 話し終わる前に切られると手がかりを取りこぼすうえ、父がせかされる。
- どう直したか: 黙ったら区切るまでの時間を1.5秒から3秒に延ばした。「〜けど」「〜て」のように途中っぽい終わり方なら、5秒まで待つ。

### 「はい」だけで見つかった扱いになった
- 何が起きたか: 同じ試用で、YOSHI さんが「はい」と答えただけで「あったね」となり、場所が記録されてしまった。
- なぜ直したか: 「はい」は相づちのこともある。見つかっていないのに記録すると、次からの順番が狂う。
- どう直したか: 「あった」「ありました」などのときだけ見つかったと判断し、「はい」「うん」だけなら「眼鏡、見つかりましたか？」と聞き直す。画面のボタンも「あった／なかった」にした。

### 実際の家の場所を使いたいが、公開はできない
- 何が起きたか: 試用ではサンプルの場所で動かしていた。YOSHI さんから、実家の場所で動かしたいが公開リポジトリには入れたくない、と言われた。
- なぜ直したか: 実際の場所でなければ役に立たない。ただ、家の中の様子は公開すべきでない。
- どう直したか: 家族用の /settings で、場所を iPad の中（localStorage）にだけ保存する形にした。「名前 | 確かめ方 | 怪しい時刻」の1行1か所で書き、時刻を書いた場所はその前後1時間に大きく加点する。リポジトリにはサンプルだけが残る。

### デモの流れが毎回同じになるとは限らなかった
- 何が起きたか: 11/6 のデモ撮影の筋書き（体まわりになし → 時刻の手がかりで次の場所 → あった）を決めたが、手がかりのない言葉でも Claude が順番を変えることがあり、毎回同じになる保証がなかった。
- なぜ直したか: 撮影の本番で順番が変わると撮り直しになり、父に負担がかかる。
- どう直したか: 順番の決め方を lib/plan.ts にまとめた。手がかりのない言葉では Claude を呼ばずにプログラムの順番で進め、Claude が理由なしで順番だけ変えた場合も使わない。怪しい時刻の前後なら「16時ごろなので、〜かもしれません。」と理由を言う（理由はプログラムが作る）。撮影の時刻がずれても練習できるよう /talk?at=16:00 で時刻を指定でき、順番が変わっていないかを tests/plan.test.ts（npm test）で確かめる。

### 家族が後から記録を見られなかった
- 何が起きたか: 探した結果は記録していたが、家族がそれを見る場所がなかった。
- なぜ直したか: 見つからなかったときに、家族が後から「どこを見たか」を知って手伝えるようにしたい。
- どう直したか: 家族用のページ /family を加えた。話したこと・見た場所・見つかった場所（休んだか）と、よく見つかる場所の回数を表示する。

### 体まわりを3回聞かれて疲れる・手がかりが生かされない
- 何が起きたか: 頭の上・首元・ポケットを1か所ずつ聞いていたので、家の中に入るまでに時間がかかった。YOSHI さんから、していたこと（例: 読書）からその場所をまず見てほしい、最初はよく置く場所だけにしてほしい、と言われた。
- なぜ直したか: 父が疲れずに、当たりやすい場所から確かめられるようにしたい。
- どう直したか: 体まわりは「念のため、頭の上や首元、ポケットにかかっていませんか？」の1回にまとめた。していたことと場所のつながりを /settings に「読書、数独 > 居間のテーブル」の形で書けるようにし（iPad にだけ保存）、話にその言葉があればその場所をいちばん先に確かめる。設定にない手がかりのときだけ Claude が候補の中から選ぶ。最初は設定の上から4か所の「よく置く場所」だけを確かめる。

### 公開している記録に、家の習慣を思わせる例を書いていた
- 何が起きたか: Claude が公開リポジトリの記録やコメントに、実家の習慣を思わせる例を書いてしまっていた。送信前の確認で止められて気づいた。
- なぜ直したか: 公開リポジトリには実際の生活の詳しい情報を入れない、というはじめの約束に反する。
- どう直したか: 一般的な例に書き換えた。例もサンプルにし、送信前に実家の場所や習慣の言葉が入っていないかを毎回確かめている。

### 本人がその場で言った場所より、設定が優先されていた
- 何が起きたか: YOSHI さんの確認で、「今日は居間じゃなくて台所で読書した」のように本人が場所を言っても、設定のつながり（読書 → 居間）の方が先になってしまう恐れがあった。
- なぜ直したか: その日にしたことは、本人の話がいちばん確か。
- どう直したか: 優先順を「本人の話 → 設定のつながり → Claude」にした。「〜じゃなくて」の前の場所は打ち消しとして数えない。「居間のテーブル」を「居間」と言っても同じ場所として扱う。

### 練習の記録が本番の回数に混ざった
- 何が起きたか: 動作確認や練習で「見つかった」を記録すると、「よく見つかる場所」の回数に混ざってしまう。YOSHI さんから、架空の確認は実際の記録と分けてほしいと言われた。
- なぜ直したか: 回数がずれると、本番で探す順番が狂う。
- どう直したか: /talk?practice=1（または ?at=…）を練習モードにした。記録は練習として分けて残し、家族ページでは別の欄にまとめ、回数には数えない。

### 探しに行っている間に、アプリが待ってくれなかった
- 何が起きたか: YOSHI さんから、父が場所を確かめに行っている間に黙っていても失敗にしないでほしい、聞いているかどうかを見せてほしい、と言われた。
- なぜ直したか: 父は歩いて確かめに行くので時間がかかる。すぐ次へ進まれると置いていかれる。
- どう直したか: 「確かめてきて、戻ったら『あった』か『なかった』と教えてください」と案内し、最大3分（声かけ1回でさらに3分）待つ。黙っている間や関係のない声は聞き流し、待っている間は画面に「戻ったら…教えてください」とマイクの印を出す。

### 一度に二か所を確かめるよう言っていた
- 何が起きたか: 確かめ方に二か所が入っていることがあり（例: 机の上と引き出し）、一度に覚えきれない。
- なぜ直したか: 一度に一つの方が、迷わず確かめられる。
- どう直したか: 一度に確かめるのは一か所だけにした。サンプルの確かめ方も一か所にしぼり、設定画面で二か所以上書くと注意を出す。2か所目からは「戻ったら教えてください」と短くする。

### 言い間違えたときに戻せなかった
- 何が起きたか: YOSHI さんから、間違えて「あった」と言ったときなどに、簡単に取り消せるようにしてほしいと言われた。
- なぜ直したか: 間違った場所が記録されると、次からの順番が狂う。言い間違いは誰にでもある。
- どう直したか: 「さっきの取り消し」「違う」で、ひとつ前の場所をもう一度聞き直せるようにした（ボタンもある）。見つかったときは「〜ですね？」と短く確かめてから保存し、違えば「どこにありましたか？」と聞いて言い直してもらう。保存したあとでも画面のボタンで記録を取り消せる。

## 2026-11-04 父の試用をふまえて

父に家で使ってもらった。探して見つかり、記録も家族ページに残った。そのうえで困ったことを4つ直した。

### 「はい」のあと無言が長く、もう一度「はい」と言ってしまった
- 何が起きたか: 父が質問に「はい」と答えたあと、アプリが聞き取りを区切るまで黙っていたので、聞こえていないと思って「はい」を何度も言い直していた。
- なぜ直したか: 返事が届いたかどうかが分からないと、話す人は不安になって繰り返してしまう。字を読むのが大変な父にも、届いたことがすぐ分かる合図が要る。
- どう直したか: 「はい」「あった」などの短い答えは、0.7秒で区切ってすぐ進むようにした。聞こえた瞬間に「ピンポン」と短い音を鳴らし、聞き取った言葉を「あなたの声：」として大きく出し、緑の大きな字で「✓ 聞こえました」と伝える。誰の言葉かも分かるようにした。

### 探しに歩いている間のつぶやきに反応した
- 何が起きたか: 父が場所を確かめに歩いている間に「どこかなあ」などとつぶやくと、アプリがそれを答えとして受け取ってしまった。
- なぜ直したか: 探している間は独り言が出るのが自然。そのたびにアプリが話し出すと、落ち着いて探せない。
- どう直したか: 探しに行っている間は、「あった」「なかったよ」くらいの短い言い切りだけを答えにして、長い話やつぶやき、テレビの声は聞き流す。案内の直後の「はい」（相づち）も、20秒は答えにしない。

### 「ほかの場所も見ますか？」と聞かれるのが負担だった
- 何が起きたか: よく置く場所になかったとき、続けるかどうかを毎回聞かれた。父は「どこかな」と自分で考えるより、次々に場所を言ってもらう方が楽だと話していた。
- なぜ直したか: 決めることが増えるほど疲れる。続けるのが普通で、やめたいときだけ言えばよい形の方が父に合う。
- どう直したか: 聞き返しをやめ、「ほかの場所を言いますね。休むときは『休む』と言ってください」と一度だけ伝えて案内を続ける。「休む」「もういい」と言うか、ボタンを押すと、見た場所を残して終われる。

### 探した経験を順番に生かしたい（呼び方も考えた）
- 何が起きたか: 試用のあと、見つかった経験を次に生かせないかという話になった。ただ「学習」と呼ぶと大げさで、何かを勝手に覚えていくように誤解されやすい。
- なぜ直したか: 家族と本人が残した記録をそのまま順番に使うだけなので、そう分かる呼び方と仕組みにしたかった。
- どう直したか: 呼び方は「探した記録をもとに順番を決める」にした。見つかった回数に加えて見つかった時刻も記録から使い、前に同じ時間帯で見つかった場所を先にして「前もこの時間に、〜で見つかりました」と理由を言う。

### 画面に出した自分の言葉を、父は結局見ていなかった
- 何が起きたか: 「はい」の言い直しを減らすために、聞き取った言葉を大きく出して「✓ 聞こえました」と表示したが、YOSHI さんが見ていると、父は画面の言葉を結局見ていない様子だった。
- なぜ直したか: 父は字を読むのが大変で、話している間は画面より相手（声）に気持ちが向いている。届いたことは、目ではなく耳で分かる形でないと伝わらない。
- どう直したか: 答えが聞こえたら、ピンポン音に加えて、父の言葉を次の言葉の頭で短く声に出して返すようにした（「なかったんですね。では、〜」「はい。〜」「あったんですね。〜ですね？」）。Claude に手がかりを聞くなどで間があくときは、返事だけ先に言う。「体のまわりにはなかったですね」のように、もともと受け止める言葉で始まるときは重ねない。ボタンで答えたときは返さない。画面の表示は家族が見る用に残した。

### タブがあると、iPad の画面の下が切れた
- 何が起きたか: YOSHI さんが iPad の Safari や Chrome で開いたとき、ほかのタブがなければ収まるが、タブがあるとタブバーの分だけ画面の下が切れた。
- なぜ直したか: 下には「あった／なかった」の答えのボタンがある。切れると押せず、画面を動かす操作も父には難しい。
- どう直したか: 話しかける画面の高さを、ブラウザが実際に見せている高さ（100dvh）に合わせ、ページ全体はスクロールしないようにした。答えのボタンは下にまとめて常に画面内に置き、狭いときは上の文字やマイクの大きさが画面の高さに合わせて縮む（それでも入らないときは上の部分だけがスクロールする）。iPad の縦・横、タブバーありを想定した高さ（640〜1000px）で、ボタンが画面内に収まることを確かめた。

### 探す時刻と、眼鏡を置いた時刻はちがう
- 何が起きたか: これまでは「怪しい時刻」（例: 毎日決まった時刻にする日課がある場所）の前後に探すと、その場所を先に案内していた。YOSHI さんが、父は眼鏡を置いてから何時間もたってから探すことが多いので、「今の時刻ならこの場所」だけでは足りない、と気づいた。
- なぜ直したか: 眼鏡があるのは、探している今していることの場所ではなく、最後に眼鏡を使って置いた日課の場所。時刻だけで決めると、置いてから時間がたつほど外れる。また、場所の一覧に書いた時刻と実際の日課の時刻が食い違うおそれもあった。
- どう直したか: /settings に「一日の流れ」（時刻 &gt; 日課 &gt; 眼鏡の置き場所）を書く欄を作り、iPad の中にだけ保存するようにした（暮らしがよく分かる情報なので、公開リポジトリにはサンプルだけを置く）。探すときは、今日もう始まった日課のうち、いちばん最近のものの場所から確かめ、「〜のあとなので、〜かもしれません」と理由を言う。外に出るときなど場所が変わらない日課は飛ばして、その前の日課の場所を見る。朝早くは前の日の夜の日課までさかのぼる。話に手がかりがあれば、これまでどおりそちらを先にする。一日の流れを書いたときは、場所の一覧の「怪しい時刻」は使わず、食い違わないようにした。設定画面で探す時刻を変えて、順番を確かめられる。
