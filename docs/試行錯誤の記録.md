# 試行錯誤の記録

試して失敗したこと、直したことを日付つきで残します。

## 2026-11-02
- 仕組みを決めた: iPad の Safari で使う Web アプリ（Next.js）。APIキーはサーバー側の .env だけに置く。
- 候補の場所と点数はプログラムで決め、Claude は父の話をもとに「候補の中だけで」順番を入れ替えて理由を一言そえる役にした。
- GitHub に送る前に APIキーや実際の家族の情報を確かめる仕組み（Claude Code フック＋git フック）を入れた。
- 手元のMacの作業環境からは npm のダウンロードが通らなかった（403）。依存パッケージの取得とビルドはクラウド側で行い、ソースだけMacのフォルダへ同期する形にした。
- 声の聞き取りテストページ /voice-test を作成（iPad Safari の webkitSpeechRecognition と speechSynthesis。サーバーには何も送らない）。iOSは読み上げもボタン操作の中で始める必要があるため、ボタンを押した時点で一度読み上げを呼ぶようにした。
- iPadで声テスト（1回目）: 聞き取り・読み上げとも「使えます」。ただし「眼鏡、どこいった？」が「メガネ」と「どこいった」の2回に分かれた。continuous=false だと「、」の短い間で認識が終わるため。→ 続けて聞き、1.5秒黙ったら止める方式に変更（前回方式と切り替えて比べられるようにした）。
- 「眼鏡」が「メガネ」とカタカナで返ることがある。→ 眼鏡/めがね/メガネ を同じものとして扱う lib/normalize.ts を追加。
- iPadのSafariは端末情報（UA）を「Macintosh」と名乗る。→ 端末の判定にUAは使わない。
- 父がテストしたとき、聞き取り中のボタンに出ていた「聞いています…」をそのまま読み上げ、それが聞き取られた。画面の文字を声に出して読むのは自然なこと。→ 聞き取り中の画面には、話してほしい言葉そのもの（「眼鏡、どこいった？」）を出すようにした。読み上げてもらえばそれが正しい入力になる。
- iPadで再読み込みせずに試すと古い版のまま動いていた（記録の形式が前のまま）。→ 画面に版（コミット番号）を表示するようにした。
